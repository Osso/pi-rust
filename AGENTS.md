# Development Rules

- Parity bar (user decision 2026-10-25, supersedes stricter wording below): port to **user-observable** parity. Exact: frozen logic/control flow for realistic inputs; user-visible output (TUI, CLI, console/stderr text, error messages users see); persistence formats (session JSONL, control DB, archives, settings/auth files) and IPC/RPC/provider wire formats, proven bidirectionally with TS fixtures. Recorded gap (one line in the module trace; no proof matrix, no new carrier/API just to represent it): adversarial or pathological inputs (wrong-typed or exotic JSON shapes, toString-throwing values, lone surrogates beyond existing carriers), OS/runtime fault shapes (entropy failure, ENOSPC/EPIPE on stdio, closed/exotic fds, IDNA edge cases), numeric extremes (>2^53, timer overflow), Node/V8/libuv oddities and scheduling races. Do not hunt for these. Unreachable faults may route through the shared uncaught authority instead of widening APIs. No panics or silent data loss on realistic paths; keep existing lossless carriers.
- Proof depth (user decision 2026-10-25, "lighter proof"): non-persistence rows close on a whole-module audit plus existing tests; each found discrepancy gets a fix with one native behavioral test, not a new frozen differential/matrix. Persistence, IPC and provider wire formats keep bidirectional frozen proof.
- Mechanical cross-lane edits are pre-cleared (user decision 2026-10-25): widening signatures to Result, propagating at callers, pub visibility, fixture/test updates in other lanes' files. Report them in the checkpoint; no prior question needed. Still ask main before semantic deviations, feature deletion, new dependencies, TS delta changes, or changing another lane's algorithms.
